# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Yagi ("Yagi - Podcasts and Audiobooks"; launcher label `Yagi`) is an Android podcast and audiobook app (app id `dev.russell.yagi`, packages `dev.russell.yagi.*`). This repository is a **hard fork** of [allentown521/FocusPodcast](https://github.com/allentown521/FocusPodcast), which is itself a heavily modified fork of AntennaPod. Upstream mergeability was abandoned in the September 2026 refactor (see `docs/REFACTOR_BASELINE.md` for the before/after numbers), so do not try to keep diffs upstream-friendly. The structure and most core classes still match AntennaPod, but several were renamed (`PodDBAdapter` → `Db`, `UserPreferences` → `Prefs`, `de.danoeh.antennapod` → `allen.town.podcast`), so upstream docs do not map 1:1. In October 2026 the fork moved to its own ids: app id `allen.town.focus.podcast` → `dev.russell.focuspodcast` and packages `allen.town.podcast.*` → `dev.russell.focuspodcast.*`. In late October 2026 it was renamed Yagi: app id and packages `dev.russell.focuspodcast` → `dev.russell.yagi`, styles `Theme.FocusPodcast.*` → `Theme.Yagi.*`, database file `focusPodcastApp.db` → `yagi.db`. Because the app id changed, Yagi installs next to FocusPodcast instead of updating it; users move their data with the database export/import. Deliberately kept from the old name: the `FocusPodcastLocal*:` download-URL prefixes in `Feed` (stored in the database, so imported FocusPodcast databases keep working), the `focuspodcast.com` / `focuspodcast-subscribe://` deep links (so links already shared still open the app), and the GitHub repository name. The repository is now `JapanColorado/Yagi`; every in-app link to it (About, changelog, issues, bug report, privacy policy in `PRIVACY.md`, the "Sent from Yagi" footer of shared episodes) goes through `core/util/ProjectLinks`, and nothing in the app points at upstream's Play listing, canny.io board, docs site, Ko-fi or email any more. Report bug writes the logcat to a file, offers it in a share sheet, and then opens the GitHub bug form with version and device filled in. The launcher, monochrome and notification icons (a Yagi antenna on deep purple) and their PNG fallbacks are generated by `scripts/make_icon.py`; edit the geometry there and rerun it rather than editing the drawables. Mixed Kotlin/Java: `app` is Kotlin-leaning, `core`/`model`/`parser`/`storage` are almost all Java. All comments and configuration are in English; only the `values-zh-rCN`, `values-zh-rTW` and `values-ja` translation resources contain non-Latin text.

The app is F-Droid-only: there are no build flavors, no Google Play / Firebase / ads / in-app-purchase code, and no pro gating. Monetisation, analytics, crash reporting, LeanCloud, Cast, cloud backup and the GoRouter service locator were all deleted rather than stubbed; do not reintroduce them.

## Build prerequisites

1. **JDK 25** to run the build (`compileSdk 37`, `minSdk 24`, `targetSdk 35`, Gradle 9.8, AGP 9.4.1, Kotlin 2.4.20; bytecode still targets Java 17). AGP 9 compiles Kotlin itself ("built-in Kotlin"): there is no `kotlin-android` plugin, kapt comes from AGP's `com.android.legacy-kapt` (the `com.android.tools.build:gradle-kotlin` classpath entry), and compiler flags go in a top-level `kotlin { compilerOptions { } }` block. Use pixi: `pixi install` fetches JDK 25 from conda-forge and `scripts/env.sh` exports `JAVA_HOME`/`ANDROID_HOME` on activation, so run every Gradle command as `pixi run <task>` (or `pixi shell` then `./gradlew ...`).
2. `scripts/check-env.sh` (a `depends-on` of most pixi tasks) verifies JDK 25 and the SDK and writes `local.properties` (gitignored) pointing at `$ANDROID_HOME` (default `~/Android/Sdk`, which must have platform 37 and build-tools 36.0.0; AGP downloads missing ones itself when the SDK licence is accepted). The Debian SDK at `/usr/lib/android-sdk` has no platforms and is unusable.
3. **Debug builds need no secrets.** `app/build.gradle` reads `secrets.properties` if it exists; if it does not, it prints a notice, uses placeholder PodcastIndex API keys, and falls back to Gradle's default debug signing config. **Release builds need a real keystore**: copy `secrets.properties.sample` to `secrets.properties` and fill in `storeFile`/`storePassword`/`keyAlias`/`keyPassword` (the same entry drives both the release and debug signing configs when present).
4. There are no git submodules. The three vendored libraries live in-tree under `lib/`.
5. Dependency resolution uses `google()`, `mavenCentral()`, `gradlePluginPortal()` and JitPack, plus one Aliyun mirror (`maven.aliyun.com/repository/public`) that exists solely because `com.beloo.widget:ChipsLayoutManager:0.3.7` (an ex-jcenter artifact) is not on Maven Central. Do not remove that entry without finding another source for it.

## Module architecture

`settings.gradle` includes 18 modules: 15 app modules plus the three vendored libraries under `lib/`. Every module applies `common.gradle`, which supplies the legacy-kapt and parcelize plugins, Java 17, viewBinding and the shared `packaging`/`lint` blocks. The root `build.gradle` copies `project.ext` into every module, because Gradle 9 deprecates reading parent-project properties by bare name. All shared versions (SDK levels, `versionCode`/`versionName`, library versions) live in `project.ext` in the root `build.gradle`.

Dependency direction (top depends on bottom):

- **app** — Activities/fragments/adapters, `MyApp` Application. Depends on core and nearly everything else.
- **core** — the workhorse: `DBReader`/`DBWriter`/`DBTasks`, `PlaybackService` + `LocalPSMP` + `ExoPlayerWrapper`, `DownloadService`, `FeedUpdateWorker`, `SyncService`, `Prefs`, widgets, Glide setup, backup/OPML.
- **playback/base** — abstract `PlaybackServiceMediaPlayer`, `PlayerStatus`.
- **storage/database** — raw SQLite `Db.java` (package `dev.russell.yagi.storage.db`, `yagi.db`, `VERSION = 13`, renumbered from AntennaPod; v8 clear voice, v9 transcripts, v10 bookmarks, v11 Podcasting 2.0 persons/soundbites, v12 per-feed video mode, v13 per-feed volume leveling), `DBUpgrade.java` hand-written ALTER ladder, `mapper/*CursorMapper`. No Room.
- **parser/feed** (RSS/Atom), **parser/media** (ID3/Vorbis chapters), **net/ssl**, **net/sync/model** + **net/sync/gpoddernet**
- **event** — EventBus payload classes only. **model** — POJOs (`Feed`, `FeedItem`, `FeedMedia`, ...).
- **ui/common** (shared views), **ui/app-start-intent** (typed Intent builders so lower modules can launch app Activities without depending on `app`), **ui/i18n** and **ui/png-icons** (resources only).
- **lib/common** (`dev.russell.yagi.common.*` — base Activity/Application, dialogs, utils), **lib/theme** (`dev.russell.yagi.theme.*`), **lib/searchpreference** (`dev.russell.yagi.searchpreference.*`). These were git submodules until Phase 1; they are now ordinary in-tree modules and may be edited freely. Their packages were renamed out of their upstream namespaces into `dev.russell.yagi.common.*`, `dev.russell.yagi.theme.*` and `dev.russell.yagi.searchpreference.*` (the handful of files that still declared a RetroMusic package were folded into the package matching their own directory), so every class in the build now lives under `dev.russell.yagi.*` and upstream AppThemeHelper / RetroMusic / SearchPreference sources no longer apply as drop-in patches.

### The big classes are split into collaborators

The seven classes that used to exceed ~1,000 lines were split by pure extraction; every public API stayed on the original class, so callers did not change. When touching one of these, look for the logic in its helpers first:

- `storage/db/Db.java` — `DbSchema` (column constants and CREATE statements), a `Dao` base class with the shared transaction wrapper, and per-table `FeedDao`, `FeedItemDao`, `FeedMediaDao`, `QueueDao`, `FavoritesDao`, `DownloadLogDao`, `DismissedWarningDao`, `AdSegmentDao`. `Db` delegates to them.
- `core/service/playback/PlaybackService.java` — `PlaybackServiceMediaSession`, `PlaybackServiceMediaBrowser`, `PlaybackServiceNotificationUpdater`, `PlaybackServiceReceivers`, `PlaybackServicePlayerCallback`, `PlaybackServiceAutoSkipper`, `PlaybackServiceAdSkipper`.
- `core/service/playback/LocalPSMP.java` — `LocalPSMPAudioFocus`, `LocalPSMPAudioEffects`, `LocalPSMPPlayerFactory`, `LocalPSMPSeeker`, `LocalPSMPPlaybackEnder`, plus `PlayerLock` and `PlayerExecutor`.
- `core/pref/Prefs.kt` — `PrefsStore` plus the `PlaybackPrefs`, `DownloadPrefs`, `UiPrefs`, `NetworkPrefs` and `SyncPrefs` objects. `Prefs` remains the single facade for both Java and Kotlin callers; add new preferences to the matching group object and expose them through `Prefs`.
- `core/service/download/DownloadService.java` — `DownloadQueue`, `DownloadPipeline`, `DownloadCompletionHandler`, `DownloadNotifier`.
- `app/fragment/FeedItemlistFragment.kt` — header, loader, menu, multi-select and pager helpers under `fragment/feeditemlist/`.
- `app/activity/MainActivity.kt` — nav drawer, fragment navigator, player sheet, intent handler and hardware-key helpers under `activity/main/`.

### Per-podcast speed, effects and ad detection

One rule everywhere: a podcast follows the global defaults until something is changed for that podcast; then it keeps its own values until "Reset to default". Settings > Playback holds the defaults ("Default playback speed" via `PlaySpeedDialog.newGlobalDefaultInstance()`, and the "Default audio effects" category: Voice, Volume leveling, Skip silence, Stereo to mono, explained by a category summary that `lib/common`'s `preference_category_title` layout can now show) and Settings > Ad skipping holds "Detect ads". The player's Audio Effects dialog (`PlaybackControlsDialog`) and a podcast's settings > Audio effects (`AudioEffectFragment`) show the same four controls in the same order, always at their effective values; the first change for a podcast calls `AudioEffectUtils.customize` (copy the defaults in) and then saves, which stores it on the podcast (`FeedPreferences.feedPlaybackSpeed`, `useFeedEffect` + skip silence, mono, `clearVoiceLevel` and `volumeLeveling`, `adSkipOverride`). Speed works the same in the player's `PlaySpeedDialog` and the podcast's speed dialog in `FeedSettingsFragment` (whose summary says whether the speed is the default or the podcast's own). Wherever a podcast has its own values, `own_settings_card.xml` (or two preference rows on the Audio effects screen) offers "Reset to default" and "Set as default"; the latter copies the podcast's values into the globals, posts the global-change events, and then resets the podcast (`AudioEffectUtils.makeDefault`, `AdSkipUtils.makeDefault`, `PlaybackSpeedUtils.makeDefault`/`setDefaultSpeed`). Unsubscribed (previewed) feeds and non-feed media always read and write the globals, so neither button shows for them. Resolution lives in `core/feed/util`: `PlayableFeedPreferences` (which prefs apply), `PlaybackSpeedUtils` (`getCurrentPlaybackSpeed`, `rememberSpeed`, `setFeedSpeed`), `AudioEffectUtils` (`isSkipSilence`/`isMono`/`getClearVoiceLevel`/`getVolumeLeveling`, `customize`, `saveFeedEffects`) and `AdSkipUtils`. Writes from possibly stale copies go through `DBWriter.updateFeedPreferences(feedId, change)` (read-modify-write of the current row); live changes reach the service's in-memory `FeedPreferences` through `SpeedPresetChangedEvent` / `AudioEffectsChangedEvent` (feed id 0 = the global default changed). The player's Equalizer button was removed: it only opened the system effect panel without an audio session, so it never affected this app.

### Video episodes (video player or audio only)

Whether a video episode opens `VideoPlayerActivity` or plays in the normal player sheet without the picture follows the same default-plus-override rule: `Prefs.isPlayVideoAsVideo` ("Video episodes" in Settings > Playback, default video) and `FeedPreferences.videoOverride` (`feeds.feed_video_override`, NULL/1/0, "Video episodes" in the podcast's settings). On top of that, "Audio only" in the video player (also Back, a downward swipe, or closing picture-in-picture) and "Watch video" in the player sheet's toolbar switch the playing episode only; that choice is kept in `PlaybackPreferences`, pinned by the service when it starts an episode and forgotten when any other episode starts or playback ends, so the notification, widgets and media session open the matching player (`VideoModeChangedEvent` refreshes them). `VideoPlayerActivityStarter.EXTRA_MEDIA_KEY` tells a freshly opened player which episode to wait for, and the most recently started player instance owns the video surface. Every entry point asks `core/feed/util/VideoModeUtils.shouldShowVideo` (or `PlaybackController.isShowingVideo`); never test `MediaType.VIDEO` alone to decide which player to open. The global default speed follows how the episode is played, not its media type: the video speed only while it is watched, the audio speed when it is listened to (`PlaybackSpeedUtils.speedTypeOf`; a podcast's own speed wins either way). Leaving the video player never pauses: `notifyVideoSurfaceAbandoned` only detaches the surface, and `ExoPlayerWrapper.setDisplay(null)` also disables the video track so audio-only playback does not decode video. The video player itself is split into `activity/video/` (`VideoPlayerLayout`: portrait/landscape ConstraintSets, insets, controls; `VideoGestures`; `SeekBarMarkers`).

Audio-only downloads: a video episode whose podcast is listened to as audio only (`DownloadRequestCreator.wantsAudioOnly`, i.e. `VideoModeUtils.isVideoPreferred` is false) downloads only its audio track. `AudioOnlyDownloader` reads the remote MP4's top-level boxes and `moov` with range requests, `core/service/download/mp4/AudioOnlyMp4Plan` (pure Java, tested by running ExoPlayer's `Mp4Extractor` over its output) keeps the audio `trak` only, rewrites its `stco`/`co64` and groups the audio chunks into range fetches, and the downloader fetches them 16 at a time and writes `ftyp | moov | mdat` in order (resumable after the last complete fetch). A 24 GB 4K episode becomes about 130 MB. The file is named `<title>.<id>.audio.m4a` and that name is the only marker (`FeedMedia.isAudioOnlyFile`/`isAudioOnlyDownload`; generated names have no other dots), the media type stays VIDEO. Playback decides local vs. stream through `VideoModeUtils.shouldStream`/`resolveStream`: an audio-only download that is to be watched streams (and is played as audio instead when streaming is not allowed), and `PlaybackService.videoModeChanged` calls `LocalPSMP.switchSource` to move the playing episode between the file and the stream at the same position. Such a stream can be far heavier than the connection (4K podcast files run at 40 to 60 Mbit/s), so "Watch video" first compares the bitrate (`core/util/VideoStreamCheck`: server file size from a one-byte range request, duration, video speed) with Android's downstream estimate and warns, and the service goes back to the downloaded audio if the stream has not advanced 10 s after the switch (`PlaybackService.checkVideoStreamStarted`). Files that cannot be cut (not MP4, fragmented, no range support) fail with `ERROR_AUDIO_ONLY_UNSUPPORTED`; up to 2 GB the whole file is then downloaded automatically (`DownloadCompletionHandler.fullDownloadInstead`), above that the app asks (`AudioOnlyDownloadUnavailableEvent` → `FullVideoDownloadDialog`, also from the download log's retry).

### Voice modes (Clear voice, Warm)

"Voice" (Original / Clear / Clear+ / Warm = `ClearVoiceLevel` OFF / LIGHT / STRONG / WARM in `model/.../playback/ClearVoiceLevel`; global `Prefs.PREF_CLEAR_VOICE`, a string, per feed `feeds.clear_voice`, an int; the values are never renumbered) replaced the old `LoudnessEnhancer` "vocal enhancement". The selector shows a one-line description of the selected mode (`R.array.clear_voice_descriptions`, `ClearVoicePreferences`). It is pure-Java DSP in `core/dsp/`: `ClearVoiceChain` runs an 80 Hz high-pass (`Biquad`) and then, for Clear/Clear+, a light `DeEsser` (split-band, Linkwitz-Riley crossover at 4.5 kHz, cuts sibilants that rise above the speech body), `SpectralDenoiser` (STFT overlap-add, minimum-statistics noise floor, decision-directed Wiener gain, reduction ramps in over 1.5 s) and `Leveler` (speech-gated AGC to -20 dBFS, RMS compressor, 3 ms look-ahead limiter at -1 dBFS); for Warm it runs `VoiceEnhancer` instead (low shelf around 180 Hz, a small dip around 3.5 kHz, the same light de-esser and a -1 dBFS limiter; no noise reduction or leveling). The old Clear voice speech EQ (300 Hz cut, 3 kHz lift) was removed because it thinned well-produced voices. Switching between Clear and Warm drains one set of stages and starts the other. `ClearVoiceAudioProcessor` wraps the chain for ExoPlayer and sits after `DownMixAudioProcessor` in `ExoPlayerWrapper`'s sink. It stays active for all 16-bit PCM and byte-copies when Off, because ExoPlayer only reads `isActive` at configure time; that is what makes live switching work. `flush()` keeps the learned noise floor/AGC, `reset()` forgets. Tune with the synthetic-signal tests in `core/src/test/.../dsp/`, not by ear alone. `Fft` lives in `core/dsp` (shared with ad detection).

### Volume leveling

"Volume leveling" (Off / Gentle / Strong = `VolumeLeveling` OFF / GENTLE / STRONG in `model/.../playback/VolumeLeveling`; global `Prefs.PREF_VOLUME_LEVELING`, a string, per feed `feeds.volume_leveling`, an int, part of the podcast's own audio effects; never renumbered) keeps podcasts at the same loudness. It is the Clear voice `Leveler` (speech-gated AGC to -20 dBFS, compressor, -1 dBFS limiter) inside the same `ClearVoiceChain`, set with `setVolumeLeveling` next to `setLevel`: with Original voice it is the only stage (no high-pass), with Warm it runs after `VoiceEnhancer`, and with Clear/Clear+ (which already level) each leveler parameter takes the stronger of the Voice and leveling values (`strongerOf`). Gentle averages the speech level over 4 s and moves at most 1.5 dB/s within +15/-12 dB, so it sets a per-podcast gain and keeps the dynamics; Strong also flattens speakers and loud moments. After `Leveler.reset()` (every episode gets a new `ExoPlayerWrapper`, hence a fresh chain) the AGC settles fast for the first 2 s of speech so a slow mode does not start at the wrong gain; a seek (`flush`) keeps the learned level. Changing between stage sets (leveling on/off with Original or Warm, Clear to Warm) drains and restarts like a Voice switch; it reaches the service through `AudioEffectsChangedEvent` like the other effects. Unlike Clear voice's live setter, `LocalPSMPAudioEffects.setVolumeLeveling` also applies to video episodes.

### Transcripts, bookmarks, Podcasting 2.0

- Transcripts: `<podcast:transcript>` picks the best type (JSON > VTT > SRT > HTML > plain) into `episodes.transcript_url/type`; fetched text is cached in the `transcripts` table (`TranscriptDao`, raw + plain `text` used by search) by `core/util/TranscriptUtils` after download and on demand. Parsers are in `parser/feed/.../transcript/`. Shown as a tab in `FeedItemExtraInfoFragment`; `EpisodeSearchOptions.Field.TRANSCRIPT` searches cached text only.
- Bookmarks: `bookmarks` table (`BookmarkDao`), `BookmarksChangedEvent`, player button, ticks on `AdMarkerSeekBar`, a tab in the player sheet and a drawer page. `app/util/PlayAtPosition.kt` is the shared "play this episode from X" path (bookmarks, soundbites).
- `<podcast:person>` and `<podcast:soundbite>` are stored as JSON TEXT (`feeds.persons`, `episodes.persons`, `episodes.soundbites`, `PodcastingJson`), kept out of list projections and loaded with the description; written only when non-null.
- Sleep timer modes (`SleepTimerMode`: duration / end of episode / end of chapter): boundary logic is the pure `SleepTimerEndCondition`; end of episode lets completion run normally and then stops before the next item (`getNextInQueue(completed)`).
- Notification custom buttons (`NotificationCustomAction`, resolver is pure): next chapter, speed cycle, sleep +15, skip ad; up to two, published as MediaSession custom actions and notification actions.

### Ad auto-skip

Ad skipping is opt-in and has no ML runtime. It is a per-feed setting whose default is global:
`Prefs.isAdSkipEnabled` (default off, shown as "Detect ads" in Settings > Ad skipping) is only the default,
and `FeedPreferences.getAdSkipOverride()` is a tri-state `Boolean` (null = follow the default, TRUE/FALSE
= the user's choice for that feed, stored in `feeds.feed_ad_skip_override` as NULL/1/0). Never read the
override as the effective value: every gate (analysis, skipping, drawing segments) goes through
`core/feed/util/AdSkipUtils.isAdSkipEnabled(FeedPreferences|Playable)`, and writes go through
`AdSkipUtils.setAdSkipForFeed`/`resetAdSkipForFeed`, which persist and then post `AdSkipChangedEvent(feedId)`
(0 = the global default changed). A feed switched on analyses and skips even while the default is off.
The feed settings screen offers "Use default / On / Off"; the player's audio-effects dialog has a
"Detect ads" switch. `core/adskip/` is
pure-Java DSP. `PcmDecoder` streams a downloaded file through `MediaCodec` to mono 16 kHz float,
`AudioFeatureExtractor` turns it into one `FeatureFrame` per half second (RMS, crest factor, spectral
flatness/centroid/rolloff/flux, low-band ratio, 8-band timbre vector, and the two "spectral floor"
descriptors `floorDb`/`floorFlatness`: the per-bin 10th percentile across the window's sub-windows,
i.e. what is still playing in the gaps between syllables). `AdDetector` listens for a music bed only:
each frame gets a bed score from the floor being both loud (above -31 dB relative to the window) and
tonal (flatness under 0.16), or from the floor being filled outright (above -21 dB, any flatness:
a produced spot with drums under the voice), the score is averaged over 10 s and cut into runs with hysteresis, edges
are re-placed on a 1.5 s average, runs closer than 10 s are merged, and confidence is the run's
*median* bed score scaled by a prior that weights duration heavily (real breaks run about 1 to 6
minutes; stings, transitions and hummy rooms produce runs under a minute). The earlier
"differs-from-the-episode-median" scoring was dropped after measuring it on 23 labelled sponsor
breaks across six shows: ad loudness, crest and flatness flip sign from show to show, and on
interview shows the guest deviates as much as any ad. Do not tune thresholds by hand; the harness
that produced the defaults (ffmpeg-decoded real episodes with sponsor chapters as ground truth,
run through the real extractor and detector on the JVM) is described in `docs/AD_SKIP_TUNING.md`.
`ChapterAdMatcher` flags chapters titled like sponsor breaks, `AdSegmentMerger` gives manual > chapter
> detected precedence, and `AdAnalyzer` is the facade. `AdAnalysisWorker` (WorkManager, unique per
media id) is enqueued from `MediaDownloadedHandler` after a download and from
`PlaybackServiceAdSkipper` the first time a downloaded episode that was never analysed starts playing,
or when ads get switched on (globally or for its feed) while such an episode is playing
(it promotes itself to foreground work with a quiet notification, since a plain worker is stopped after about ten minutes; completion is remembered in `Prefs.isAdAnalyzed`, a string-set preference, because "no ads found"
and "never run" look the same in the table). It stores every result with confidence >= 0.3 in the
`ad_segments` table (`AdSegmentDao`, added in DB version 4; version 5 replaced the old per-feed opt-out
column `feed_ad_skip` with `feed_ad_skip_override`, mapping 1 to NULL and keeping 0); the sensitivity preference is applied at playback
time, so changing it needs no re-analysis. `PlaybackServiceAdSkipper` runs on the service's one-second
ticker next to the intro/ending skipper: it only skips when playback *entered* a segment within a 3 s
window, treats a seek into the middle as "let it play", posts `AdSkippedEvent` (the app shows the Undo
snackbar and answers with `AdSkipUndoEvent`), and never shows UI itself. The detector's honest limits:
host-read ads with no music bed (ATP-style) are invisible to it, and intro/outro theme music and
in-show music segments are the likely false positives, which is why segments are drawn on
the seek bar and can be disabled or deleted per episode.

### How the layers talk to each other

- **core → app callbacks via `ClientConfig`.** `MyApp.onCreate` calls `ClientConfig.initialize(context, DownloadServiceCallbacksImpl())`, which also initialises `Db`, `Prefs`, `NetworkUtils` and the sync settings. Receivers and workers that may start in a fresh process call `ClientConfig.ensureInitialized(context)`, which throws if the app never ran. `DownloadServiceCallbacks` (PendingIntents into app Activities) is the only interface core needs from app; if core needs something else only app knows, extend it rather than adding a module dependency.
- **EventBus (greenrobot) is the main cross-layer channel.** Subscriber indexes are kapt-generated: `dev.russell.yagi.ApEventBusIndex` (arg in `app/build.gradle`) and `dev.russell.yagi.core.ApCoreEventBusIndex` (arg in `core/build.gradle`), both installed in `MyApp.onCreate`. A `@Subscribe` method in a module without an `eventBusIndex` kapt arg will not be indexed.
- **RxJava2** for DB/network work off the main thread (`subscribeOn(Schedulers.io()).observeOn(AndroidSchedulers.mainThread())`), with a global handler in `app/.../error/RxJavaErrorHandlerSetup`.
- **Background work:** `DownloadService` is a foreground Service, not WorkManager. WorkManager is used for `FeedUpdateWorker` (scheduled by `core/util/download/AutoUpdateManager.java`) and `WidgetUpdaterWorker`.

## Gotchas

- ExoPlayer's `AudioProcessingPipeline` calls `queueEndOfStream()` on a processor again on every pass once the processor before it has ended, and the sink waits for the pipeline to end at the end of an episode, at every speed change and at some discontinuities. A custom `AudioProcessor` must therefore treat repeated calls as one, or playback hangs there (test against the real pipeline, as `PlayerAudioProcessorChainTest` does). `SilenceSkippingAudioProcessor` does not: it would loop its buffer forever, which is why `core/dsp/PlayerAudioProcessorChain` only lets the first call through.
- `app/build.gradle` has a `copyLicense` task hooked to `preBuild` that copies the root `LICENSE` to `app/build/generated/license-assets/LICENSE.txt`; that directory is registered as an extra `assets` srcDir. It no longer writes into the source tree — do not reintroduce a source-tree write.
- Uncaught exceptions crash the app normally. `lib/common/.../crash/CustomCrashHandler` (a Cockroach-style handler that swallowed main-thread exceptions and finished the failing Activity through hidden APIs) is no longer installed: on Android 17 the finish step fails, so a swallowed lifecycle exception left a windowless Activity and an ANR instead of a crash. Do not reinstall it.
- ProGuard rules are in `app/proguard.cfg`; release enables `minifyEnabled` and `shrinkResources`. AGP 9 only accepts `proguard-android-optimize.txt` as the default file, so `proguard.cfg` adds `-dontoptimize` to keep the unoptimised R8 output the app has always shipped; `gradle.properties` also keeps `android.enableR8.fullMode=false` and `android.enableJetifier=true` (both deprecated, removed in AGP 10; see the comments there).
- **detekt is a build gate.** Config lives in `config/detekt/detekt.yml`; it starts from detekt's
  default config and switches off everything stylistic (naming, complexity, `MagicNumber`,
  `MaxLineLength`, ...) so the gate only reports likely bugs. The plugin is detekt **2.0.0-alpha.6** (`dev.detekt`), the only detekt that understands Kotlin 2.4; move to 2.0 stable when it ships. `failOnSeverity = Info` in the root `build.gradle` makes any finding fail (detekt 1.x's `maxIssues: 0`).
  `UnsafeCallOnNullableType`, `PrintStackTrace` and `EmptyCatchBlock` must stay at zero with no
  baseline entry; there is no `config/detekt/baseline.xml` and adding one for those three is not
  allowed. Deliberate exceptions carry `@Suppress("RuleName")` next to a `// detekt: ...` comment
  saying why. Note that `UnsafeCallOnNullableType` needs type resolution, so the root
  `build.gradle` chains `detektDebug` onto `detekt`; running detekt therefore compiles first.
- **The Kotlin `!!` count is 0 and ratcheted there.** `scripts/bangbang.max` holds `0`, enforced by
  `pixi run nn` (a grep) and, independently, by detekt's `UnsafeCallOnNullableType`. Do not raise
  the max; rewrite the null handling instead.
- **`core` compiles Kotlin with `allWarningsAsErrors`** (`core/build.gradle`). It has only a
  handful of Kotlin files, so keeping them warning-free is cheap. `app` deliberately does not.
- All UI uses ViewBinding (ButterKnife was removed). kapt runs two processors (Glide, EventBus) and is the usual source of opaque build errors.
- **`pixi run lint` passes.** Three modules carry deliberate suppressions: `lib/theme/lint.xml` and `lib/common/lint.xml` downgrade `RestrictedApi` to a warning (vendored theme/preference code reaches into androidx internals that have no public equivalent), and `PlaybackService`/`PlaybackController`/`DownloadService` carry `@SuppressLint("UnspecifiedRegisterReceiverFlag")` on their pre-Android-13 `registerReceiver` branch (written when androidx.core resolved to 1.7.0, which has no `ContextCompat.registerReceiver`; WorkManager 2.10 now pulls in 1.12, so they could move to it). Cursor tinting now uses `TextView.setTextCursorDrawable` on API 29+ and only falls back to reflection below that.
- `CONTRIBUTING.md` asks not to upgrade dependencies or build tools without a concrete reason. As of the 2026-10 upgrade everything is on its latest release except deliberate holds: commons-io stays 2.5 (newer FileUtils/IOUtils need `java.nio.file`, API 26+), ExoPlayer is the last 2.x (2.19.1; Media3 is a migration), RxJava stays on 2.x, Glide on 4.x (5 is a migration). minSdk 24 is set by the libraries (current AndroidX needs 23, WorkManager 2.12 needs 24). Before bumping a JVM library, check it does not reach `java.nio.file`/`java.time` on a code path the app uses: jsoup's `Jsoup.parse(File)` does since 1.17, so pass it a stream. Also check that a new dependency does not bundle `org.xmlpull`/`xpp3`/`kxml2` classes (`./gradlew :app:dependencies --configuration releaseRuntimeClasspath`): a bundled `XmlPullParserFactory` shadows the platform's and breaks every feed parse, which is what `WebDavSyncerDemo` 0.0.7 did.
- The only long-lived branch is `main`.
- `docs/REFACTOR_BASELINE.md` records the metrics the refactor drove to zero (`!!`, `printStackTrace`, empty catches, Rx chains without `onError`, CJK text outside translations, detekt findings). Treat those zeros as invariants when adding code, not as a one-off cleanup.
- Known follow-ups not yet done: add `@Nullable`/`@NonNull` to the Java model/core getters that the `!!` sweep had to guard on the Kotlin side, and turn on Kotlin warnings-as-errors for `app` (only `core` has it).
